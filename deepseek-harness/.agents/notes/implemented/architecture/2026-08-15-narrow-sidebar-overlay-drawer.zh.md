# Agent Note：窄视口侧边栏重新展开改为覆盖式抽屉

Status: implemented

[English](2026-08-15-narrow-sidebar-overlay-drawer.md) | 中文

## 问题

低于 `SIDEBAR_AUTO_COLLAPSE` 断点时侧边栏自动折叠为 56px 图标栏，手动切换通过 `narrowExpanded` 覆盖重新展开。重新展开把宽度偏好重新喂回同一个三列让步链，因此在手机上展开的 280px 侧边栏与中心列在流内共享视口：390px 视口下中心让步到 110px——完全不可用，正是移动端用户报告的「挤压变形」。链注释承诺的是「over the squeezed center（覆盖在被挤压的中心之上）」，但求解器没有覆盖概念；中心作为最后兜底吸收了全部差额。

## 决策

窄视口下的手动重新展开现在渲染为**覆盖式抽屉**：

- grid 保持**零侧边栏轨道**（`0px minmax(0, 1fr) 0px`），中心永不让步——任何窄尺寸下都占满视口宽度。
- 侧边栏列脱离文档流（`position: absolute`、`z-index: 30`、左侧锚定、带阴影），以抽屉宽度展开渲染：侧边栏偏好，或宽屏偏好关闭时的契约默认值，**钳制到 `viewport - 24`**，保证抽屉旁至少露出 24px 内容。
- 抽屉下方是**点击即关闭的遮罩**（`z-index: 25`）；点击它调用与打开时相同的 `toggleSidebar`，store 语义（偏好不动、翻转 `narrowExpanded`）保持不变。
- 抽屉打开时不渲染拖拽手柄；`data-sidebar-overlay` 标记 frame 供 CSS 使用。

宽视口完全不受影响：`overlaySidebar` 为 `narrow && narrowExpanded`，断点以上的行为与之前完全一致。跨越断点时 `narrowExpanded` 覆盖仍会被丢弃（stores.ts `setNarrow`），回到宽屏即恢复挤压前的布局。

## 备选方案

- **流内重新展开（现状）。** 否决：这正是被报告的挤压问题；手机尺寸下中心列没有任何可用宽度。
- **抽屉按完整偏好宽度、不钳制。** 否决：宽屏拖拽出的偏好（最高 420px）可能超过手机视口；钳制到 `viewport - 24` 保证抽屉完整落在屏幕内。
- **选择后自动关闭抽屉。** 推迟：会话/工作区选择目前保持抽屉打开；选择即关闭是后续的交互决策，不是布局正确性修复。

## 后果

- 手机/平板（1024px 以下）用户任何时刻都拥有全宽中心列；侧边栏要么是 56px 图标栏，要么是带遮罩的覆盖式抽屉。
- 抽屉宽度是派生值（`drawerWidth`），从不写回 store：宽度偏好穿越窄屏会话保持不变。
- `data-sidebar-overlay` 与遮罩是新的 frame 契约：未来的窄屏专属覆盖层叠加必须遵循侧边栏 `z-index: 30` / 遮罩 `z-index: 25` / shell 覆盖层 `z-index: 20` 的顺序。
- 覆盖：app-frame 规格断言零轨道、全宽中心、抽屉 owner props、遮罩存在与点击关闭，以及手机钳制（新规格）；桌面行为规格未改动且全绿。
